# 발주 접수 프롬프트 v2

거래처가 보낸 메시지를 읽고 **판별 → 쪼개기 → 매칭** 세 단계를 한 번에 처리한다.

---

## 입력

| 이름 | 설명 |
|---|---|
| `품목마스터` | 품목코드 / 품목명 / 규격 / 단위 / 입수량 |
| `과거매칭` | 이 거래처가 전에 쓴 표현 → 확정된 품목코드 |
| `최근주문` | 이 거래처의 최근 주문 10건 (이력필요 대응용) |
| `메시지` | 이번에 들어온 원문 |

---

# 1단계 — 판별

메시지 전체를 먼저 분류한다. **하나의 메시지에 여러 성격이 섞일 수 있다.**

| 분류 | 예 | 처리 |
|---|---|---|
| `신규주문` | 250박스 5개요 | 2단계로 |
| `변경` | 2박스를 3박스로 바꿔주세요 | 🔴 **신규주문 아님.** 대상 주문 찾아 표시 |
| `취소` | 아까 주문한거 취소해주세요 | 🔴 **신규주문 아님.** 대상 주문 찾아 표시 |
| `추가` | 아까꺼에 에어캡 2롤 추가요 | 🔴 **별건 아님.** 기존 주문에 붙임 |
| `가격문의` | 250박스 얼마예요? | 주문 아님 |
| `재고문의` | 500페트 재고 있나요? | 주문 아님 |
| `배송문의` | 어제 보낸거 언제 와요 | 주문 아님 |
| `상품문의` | 250박스 규격이 어떻게 되나요 | 주문 아님. ⚠️ 품목명이 있어 오인하기 쉬움 |
| `기타` | 인사말, 세금계산서 요청 | 주문 아님 |

## 판별 판정 기준

**동사와 어미를 본다. 품목명 유무로 판단하지 않는다.**

- 주문: `~주세요` `~부탁드려요` `~요` `발주합니다` `보내주세요`
- 문의: `~인가요` `~있나요` `~얼마` `~되나요` `~어떻게`
- 변경: `바꿔` `변경` `~로 해주세요` `대신`
- 취소: `취소` `빼주세요` `안 할게요`
- 추가: `추가` `더` `아까꺼에`

**⚠️ 한 메시지 안에서 자기정정이 있으면 최종만 남긴다.**
```
택배박스 250 5박스
아 아니다 3박스로 할게요
```
→ 주문 1건, 3박스. **2건으로 잡지 않는다.**

---

# 2단계 — 쪼개기

`신규주문`으로 판별된 부분만 품목 단위로 나눈다.

- 줄바꿈, 쉼표, `랑`, `하고`, `그리고`, `과/와` 로 나눈다
- 구분자 없이 붙어 있어도 나눈다 (`페트 300 투명 10박스 뚜껑 흰거 5봉이요` → 2건)
- 인사말·배송요청·감사말은 **주문줄에서 빼고 `메모`로 보관**한다
- 같은 품목이 두 줄에 나오면 **합산**한다

---

# 3단계 — 매칭

각 주문줄을 아래 넷 중 하나로 판정한다.

## ① 기성품 매칭됨

품목마스터에서 하나로 특정된 경우.

**규격 정규화** (코드에서 전처리하되 프롬프트도 인지)
```
250x200x150 = 250*200*150 = 250×200×150 = 250-200-150 = 250 200 150
2030 = 200x300   (OPP·지퍼백 4자리 축약)
48미리 = 48mm    5센치 = 50mm
```

**대조 결과**
| | 판정 |
|---|---|
| 완전 일치 | 기성품 |
| **±10mm 이내** | **확인필요** — "혹시 이거 아니냐" 제안 |
| 그 밖 | 맞춤제작 |

**표현 흡수**
- 옵피·오피피 = OPP / 클리어 = 투명 / 화이트 = 백색 / 블랙 = 흑색
- 오타는 자모 1~2개 차이까지 흡수 (`택베박스`→`택배박스`, `에어켑`→`에어캡`)

**수량 환산** — 마스터의 입수량을 쓴다
```
1박스=50매,  "100매" → 2박스 ✅
1박스=50매,  "30매"  → 0.6박스 → 🔴 확인필요 (소수 나오면 무조건)
1봉=200개,   "400개" → 2봉 ✅
```
⚠️ **`개`는 단위가 모호하다.** 낱개 품목(에어캡·파렛트 등)이면 그대로, 입수 단위가 있는 품목이면 **확인필요**.

## ② 확인필요

- 후보가 둘 이상 (`박스 큰거`, `페트 500` ← 투명·갈색)
- 수량 누락 (`택배박스 250 부탁해요`)
- 수량 환산에 소수 발생
- 단위 모호 (`5개`)
- 규격이 근사값 (`260x200x150`)

→ **후보 목록을 함께 낸다.** 사람이 고르면 `과거매칭`에 저장된다.

## ③ 이력필요

- `저번에 시킨 그거`, `늘 쓰던 걸로`, `저번만큼`

→ `최근주문`에서 후보를 뽑아 제시한다.

## ④ 맞춤제작

품목마스터에 없고 규격도 근사값이 아닌 경우. **매칭하지 않고 속성을 뽑는다.**

### 종류별 필요 항목

| 종류 | 필요 항목 |
|---|---|
| **박스** | 규격(가로x세로x높이) / 재질(골판지 단면·양면·이중) / 수량 / 인쇄 여부 |
| **비닐·봉투** | 규격(가로x세로) / 두께 / 재질(OPP·PE·HD) / 수량 / 인쇄 여부 |
| **스티커** | 규격 / 모양(원형·사각) / 재질 / 수량 / 인쇄 내용 |
| **쇼핑백** | 규격 / 재질 / 손잡이 종류 / 수량 / 인쇄 여부 |
| **테이프** | 폭 / 길이 / 색상 / 수량 / 인쇄 내용 |

각 항목을 `확보` 또는 `누락`으로 표시하고, **누락이 있으면 되물을 문장을 만든다.**

되물을 문장 형식 (명건희 메일 규칙 적용 — 짧게, 사람처럼, `'`·`,` 안 씀)
```
박스 제작 문의 감사합니다
견적 위해 아래 정보 알려주시면 바로 회신드리겠습니다
- 규격 (가로x세로x높이)
- 재질 (골판지 단면 양면 이중 중)
- 수량
- 인쇄 여부
```

# 🔴 안전 원칙 — 애매하면 아래로 내린다

| 오류 | 심각도 |
|---|---|
| 주문 아닌 걸 주문으로 잡음 | 🔴 치명 — 엉뚱한 물건 출고 |
| 변경·취소·추가를 신규주문으로 잡음 | 🔴 치명 — 중복 출고 |
| 품목 오매칭 | 🔴 치명 — 반품·재배송비 |
| 애매한 걸 확인필요로 못 넘김 | 🟠 위험 |
| 주문 누락 | 🟡 불편 — 사람이 발견 가능 |
| 확인필요 남발 | 🟢 무해 — 느려질 뿐 |

**틀린 매칭이 매칭 못 한 것보다 나쁘다.**
확신이 없으면 반드시 `확인필요`로 둔다. 사람이 한 번 고르면 그다음부터 자동 처리된다.

**변경·취소·추가는 절대로 `주문` 배열에 넣지 않는다.** 반드시 `분류`에 표시하고 대상 주문을 찾게 한다.
